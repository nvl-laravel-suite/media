# S3 and object storage

NVL Media supports Amazon S3 and S3-compatible services through Laravel Filesystem and `league/flysystem-aws-s3-v3`. Original objects, generated variations, remote reads, signed URLs, range delivery, reconciliation, and disk migration use the same package abstractions.

## Recommended storage model

Keep the bucket private. A public Media record is reusable and publicly deliverable according to `MediaAuthorization`, the package asset route, and your CDN policy; it does not need a public object ACL.

Modern Amazon S3 buckets commonly use Bucket Owner Enforced Object Ownership, which disables ACLs. NVL Media therefore omits per-object visibility options on S3 by default. Set `MEDIA_S3_USE_ACL_VISIBILITY=true` only for a bucket that deliberately accepts `public-read` and `private` ACLs.

Private media must use temporary signed package routes or temporary disk URLs. It never falls back to an unsigned object URL.

## Laravel disk configuration

```php
// config/filesystems.php
's3' => [
    'driver' => 's3',
    'key' => env('AWS_ACCESS_KEY_ID'),
    'secret' => env('AWS_SECRET_ACCESS_KEY'),
    'region' => env('AWS_DEFAULT_REGION'),
    'bucket' => env('AWS_BUCKET'),
    'url' => env('AWS_URL'),
    'endpoint' => env('AWS_ENDPOINT'),
    'use_path_style_endpoint' => env('AWS_USE_PATH_STYLE_ENDPOINT', false),
    'throw' => true,
    'report' => true,
],
```

```dotenv
MEDIA_FILESYSTEM_DISK=s3
MEDIA_S3_USE_ACL_VISIBILITY=false
AWS_ACCESS_KEY_ID=...
AWS_SECRET_ACCESS_KEY=...
AWS_DEFAULT_REGION=eu-central-1
AWS_BUCKET=example-media
```

Add S3 to the package allowlist:

```php
'allowed_disks' => ['local', 'public', 's3'],
```

For MinIO, R2, Spaces, or another compatible service, set `AWS_ENDPOINT`, path-style mode when required, and the correct public/CDN `AWS_URL`. Add its disk name to `media.allowed_disks` before callers may select it.

`throw=true` is required for the supported production profile so transport, authorization, and quota failures become explicit exceptions. `nvl:media:doctor --production --strict` fails when an allowlisted production disk does not throw.

## Object keys and filenames

Media uses normalized relative paths and rejects traversal, null bytes, and unsafe variation names. It does not create directory markers because S3 prefixes are not directories.

Original objects use cryptographically random opaque names under `media.root_folder` and the slot path; only the validated canonical extension is retained. Display filenames never become executable object keys. Variations use immutable random object paths below `media.conversions_folder`, while database labels provide stable named lookup. A representative layout is:

```text
media/articles/{owner-id}/gallery/{64-hex-random}.jpg
media/articles/{owner-id}/gallery/conversions/{source-random}-thumb-{random}.webp
```

To include actual dimensions:

```php
'variation_naming' => [
    'pattern' => '{basename}--{label}-{width}x{height}.{extension}',
],
```

Changing the pattern changes derived object paths. Deploy the configuration and run a controlled regeneration before removing old objects.

## IAM boundary

Grant the application only the actions it uses for the configured prefix: object read/write/delete, multipart initiation/part upload/completion/abort, and list access where reconciliation or missing-state multipart recovery needs it. Scope permissions to the bucket and prefix. Do not expose application AWS credentials to browsers.

Multipart is disabled by default and supported as an opt-in 2.x production capability. When enabled, the package’s first-party S3-compatible gateway persists encrypted provider upload state, signs fixed-size parts with content length and SHA-256, completes with the persisted part inventory, verifies path/size/checksum/object identity, and can recover by inspecting an object after an interrupted completion response. Because AWS SHA-256 multipart checksums can be composite, ambiguous provider checksum metadata is verified with a streamed whole-object SHA-256 read. If provider state was not persisted, scheduled pruning finds uploads only by the exact server-owned object key and aborts matching uploads. Disabled deployments use the rejecting gateway. Normal server-proxied uploads require no multipart gateway.

AWS recommends multipart upload for objects around 100 MB and larger. Keep package part count, part size, session lifetime, total size, and checksum settings within the stricter of package, provider, and application limits.

To enable direct uploads, configure central locks:

```dotenv
MEDIA_MULTIPART_ENABLED=true
MEDIA_MULTIPART_LOCK_STORE=redis
MEDIA_MULTIPART_LOCK_SECONDS=300
MEDIA_MULTIPART_LOCK_WAIT_SECONDS=30
```

Every completed direct upload remains `pending_scan` until an out-of-band scanner submits matching `MediaScanResultData`. Schedule `nvl:media:multipart:prune` for expired and retryable cleanup sessions. Grant multipart-list permission for missing-state recovery; if that is unavailable, configure the provider’s incomplete-multipart-upload lifecycle rule as a backstop. Before production rollout, run the PHP/Laravel/PostgreSQL/Redis/MinIO integration matrix against the target provider and require a clean `nvl:media:doctor --production --strict` result.

## Image processing with S3

Spatie Image operates on local files. NVL Media leases an S3 object to a temporary local file, processes it with GD/Imagick/libvips, uploads the result, then releases the temporary file in `finally`. Workers therefore need:

- enough temporary disk for the largest decoded source and output;
- memory appropriate for decoded pixel dimensions, not only compressed byte size;
- the selected driver and WebP/AVIF encoders;
- S3 network access and credentials;
- a durable queue for production workloads.

The upload size limit and `image_constraints` dimensions are independent controls. Keep both bounded.

## Delivery and CDN

The default package public asset route provides stable versioned URLs, ETags, conditional requests, HEAD, byte ranges, and immutable public cache headers. Private delivery uses signed URLs and private/no-store caching.

If `media.assets.remote_public_delivery` is changed from `route`, verify that the selected disk/CDN enforces the intended public boundary and that object keys do not expose private media. Never use a public bucket policy over a prefix that may contain private objects.

## Deployment checklist

1. Configure the disk with `throw=true`.
2. Keep ACL visibility disabled unless the bucket explicitly supports ACLs.
3. Add the disk to `media.allowed_disks`.
4. Configure Redis-backed mutation/deduplication locks and a durable Media queue.
5. Bind a real `MediaContentScanner`. Keep multipart disabled unless direct uploads are required; when enabled, satisfy every multipart production gate above.
6. Run `php artisan nvl:media:doctor --production --strict --format=json`.
7. Run a non-production live probe: `php artisan nvl:media:reconcile --disk=s3 --live-write --cleanup`.
8. Upload one private and one public-reusable fixture and verify delivery authorization.
9. Start the dedicated Media worker and verify all variations.
10. Before migration, run `nvl:media:migrate-disk --dry-run`.
11. After migration, run `nvl:media:reconcile --production --disk=s3 --orphans`.

Production reconcile cannot be combined with `--live-write`. Orphan cleanup remains a separate explicit operation and requires both `--cleanup-orphans` and `--force` in production.
